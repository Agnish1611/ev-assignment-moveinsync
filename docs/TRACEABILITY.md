# Requirement Traceability

Traceability between case study requirements and verification evidence.

| Requirement from case study | Evidence required | Status |
|---|---|---|
| Battery floor / charger capacity / trip timing | Validator + mutation tests + property tests | Phase 2 complete & verified: `PlanValidatorTest`, `PlanValidatorMutationTest` (24 mutations), `PlanValidatorPropertyTest` (1,000 jqwik trials), `PlanValidatorDeterminismTest` (200 permutations); jacoco line >= 90%, branch >= 80% |
| Minimise backups, then cost, with explanation | Objective tuple docs + tests + README trade-off section | Phase 4, 5, 7. The README trade-off section and `docs/DESIGN_NOTE.md` state fewer backups first, then change penalty plus charging cost |
| Re-plan within 2 s, minimal changes | Drift scenario test + latency metrics + replan_run table | `LadderReplanTest` moves the 22 percent trip and at most two others inside a 2 second deadline (D22). `LadderTriggerTest` covers an added trip, a cancellation, cab removal, and a cab below the floor (D26). `PlanPublicationIT` writes `replan_run` in the same transaction as the head (D27). `ServiceMeters` records `ev.replan.latency` by tier, plus rejection, conflict, backup, gap, and safe-patch counters (D30). `DriftStormTest` applies 100 cab readings inside a 2 second deadline and the validator accepts the plan (D31). `ChargingBenchmark` is 1.908 ± 0.132 ns/op. k6 on `GET /actuator/health` is 12,401.5 req/s, p50 684 µs, p99 1.7 ms (`docs/reports/PROOF_LATENCY.md`) |
| Charger failure re-plan | Charger-failure test | `ChargerTriggerTest` moves an active session off the failed plug. `TriggerReplanValidatorTest` checks that plan at 15 percent (D26) |
| Why unassigned (reasons) | Counterfactual probe tests + reason-code docs | `AssignmentDiagnosis` and `AssignmentDiagnosisTest`. Evidence is watt-hours and a UTC plug window (D25). `ServiceMeters` counts each reason code (D30) |
| Per-cab timeline with SoC at each step | Timeline endpoint + tests | Generator: `CabTimeline` and `CabTimelineTest`. `HttpAccessIT` reads `GET /v1/cabs/{id}/timeline` from the published stops and sessions (D29). Version reads are cached by tenant, shard, and version (D30) |
| Heuristic + complexity + lower bound | Javadoc Big-O + lower-bound report in `docs/reports/` | Phase 5, 6, 7 |
| Independent validator run on every result | ArchUnit isolation test + validator invoked in publish path | `ValidatorArchitectureTest` keeps the validator off the planner. `PlanPublication` stores a head only when `PlanValidator` accepts the plan (D27). HTTP reads that head. `POST /v1/plans` records a job and does not publish (D29) |
| 300-cab case in < 30 s with report | Benchmark test + committed report | Planner solve: `BenchmarkScenarioTest` and `docs/reports/PLANNER_300CAB_REPORT.md`. Validator latency: `docs/reports/VALIDATION_300CAB_REPORT.md` |
| Concurrency + failure tests | Named tests listed in README | `PlanPublicationIT` runs two writers on one shard: one head advances, the other conflicts (D27). `DeliveryTest` drops a duplicate, drops a reordered older sequence, and dead-letters a poison payload (D28). `WorkerCrashTest` kills a solve before the sequence is committed and the replacement finishes it (D31). `ConnectionDropIT` leaves the head on the committed version when the next connection fails. `OutboxRelayIT` publishes the outbox once. `HttpAccessIT` checks cross-tenant reads and role checks (D29). `DriftStormTest` is the 100-cab storm |
| Throughput and p50/p99 | k6/JMH output in README with machine specs | `docs/reports/PROOF_LATENCY.md` and the README performance section. k6: 12,401.5 req/s, p50 684 µs, p99 1.7 ms on health. JMH: 1.908 ± 0.132 ns/op. Scale curve 18 ms, 27 ms, 164 ms, 1,012 ms at 1x, 2x, 5x, 10x. Apple M4, 10 cores, 16 GB, Temurin 21.0.13. The 300-cab solve remains 24.258 s |
| One-command run | CI job doing `docker compose up` smoke test | `docker compose up --build` starts two app instances, Postgres, Kafka KRaft, Schema Registry, Keycloak realm ev, Prometheus, and Grafana (D32). The CI workflow already runs `docker compose up -d` and was not edited |
